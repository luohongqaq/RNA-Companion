# 上下文压缩

上下文压缩为长时间聊天准备窗口交接：当当前 session 的历史逐渐接近容量时，后台将较早的对话整理成摘要，再与切换前尚未被摘要覆盖的原文一起交给下一个 session。用户看到的 conversation 可以继续，角色也能带着必要的背景接话。

## 功能

| 功能 | 作用 |
| --- | --- |
| 准备交接摘要 | 在窗口接近容量时提前整理固定范围的对话和继承材料。 |
| 校验与发布 | 检查摘要结构、来源和 token 预算，将通过的结果保存为等待采用的快照。 |
| 会话交接 | 在完整轮边界核对摘要和后续原文，将旧 session 封存并建立后继 session。 |

## 设计特点

### 摘要与最近原文一起延续对话

单纯保留最近几轮容易丢掉更早的约定和话题；把所有历史都压成摘要又会失去刚刚说过的话的细节。这里提前固定一个完整轮边界，整理边界以前的内容；准备期间产生的新原文留在摘要之后。切换时，下一窗口同时继承摘要和连续的原文尾部。

### 提前准备，到了边界进行窗口交接

当前默认窗口额度为 3000 token，继承摘要、继承原文和当前 session 新原文都按实际用量计入。

| 时点 | 默认用量 | 系统动作 | 对聊天的影响 |
| --- | --- | --- | --- |
| 尚未到准备线 | <80% | 继续使用当前窗口。 | 正常聊天。 |
| 达到准备线 | 80% | 固定当前完整轮作为摘要的覆盖上界，在后台准备交接摘要。 | 聊天可以继续；摘要准备好也不会立即切换。 |
| 准备后继续聊天 | 80%-95% | 摘要处理固定范围；新产生的对话保留为后续原文。 | 例如角色继续询问目的地，新的问答不会被塞进已经冻结的摘要范围。 |
| 达到等待线 | 95%      | 进入等待交接；摘要就绪且来源、连续尾部和容量检查通过时切换。 | 后续生成可能需要等待材料就绪；切换成功后继承摘要和尾部继续对话。 |

### 摘要关注角色如何接话

摘要以当前角色的视角整理上下文，除了历史主线，还可以表达当前话题、双方约定、必要指代、用户情绪、未解决问题以及正在进行的场景。角色设定帮助模型保持身份与语气，但不能替代对话事实。这样做的目标是让下一窗口理解“现在聊到哪里”，而不仅是得到一份按时间排列的聊天流水账。摘要按内容作用分区，具体保留哪些内容取决于对话和可用依据：

| 摘要内容 | 保留什么 | 对后续聊天的作用 |
| --- | --- | --- |
| 历史主线 | 重要经历、讨论结论和必要背景，区分现实、剧情、设定与假设 | 让角色了解前情，避免把虚构内容当作现实事实。 |
| 约定与承诺 | 双方确认的决定、偏好、边界和承诺，以及有依据的日期和状态 | 帮助角色延续有效约定，区分已决定和仍待完成的事。 |
| 当前与最近话题 | 摘要边界处仍在继续的主线，以及最近交流的话题 | 帮助角色判断对话聊到哪里，避免重新开场或跳过话题。 |
| 称呼与指代 | 理解当前对话所需的人物称呼、代称和对象关系 | 减少换窗口后把“他”“那个项目”等指代弄错。 |
| 用户情绪 | 有依据的用户情绪及其时间、当前状态 | 帮助角色理解当时的感受，避免直接把过去情绪当成现在的状态。 |
| 未解决问题 | 继续当前话题所需、尚未解决的问题 | 让角色知道哪些问题仍需要回应，不把未回答当作同意。 |
| 场景状态 | 有依据的剧情地点、时间、人物、正在进行的动作及角色知情范围 | 在角色扮演时保持场景连续；普通聊天没有相关场景时可以留空。 |
| 话题关键词 | 本次 session 涉及的主题、实体和项目等关键词 | 为后续回复提供简短的话题背景。 |

### 来源固定，失败可以恢复

后台整理的是登记时固定的会话前缀，而不是不断追逐最新消息；继承内容也使用固定引用。生成和校验分阶段保存，进程中断后可以从已保存的阶段继续。正式切换前还会重新核对来源、原文尾部的连续性及新窗口容量，减少旧结果覆盖新状态或遗漏对话的风险。
